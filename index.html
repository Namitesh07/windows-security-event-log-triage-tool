How review priority works

High: 60+ points, investigate promptly. Medium: 30–59 points, investigate with context. Low: 1–29 points, validate routine activity. Informational: 0 points, context only. Each finding shows its rule and contributing points. Scores are educational priority aids and are not added into a dataset risk score.

    FIELD GUIDE

    How to Think Like a SOC Analyst

    1. Identify the event.
    2. Understand what happened.
    3. Identify the affected user or system.
    4. Decide whether the activity is expected.
    5. Look for related events.
    6. Correlate authentication and privilege activity.
    7. Gather additional evidence.
    8. Decide whether escalation is required.
    One security event rarely tells the entire story. Analysts build context by correlating multiple events.

    A detection is a reason to investigate, not proof that an attacker is present.

    COLLECT THE EVIDENCE

    Choose an event export format

    1. For CSV, export selected events from Windows Event Viewer with an Event ID and timestamp column.
    2. For XML, use Windows Event XML containing one Event or an Events collection. Named EventData fields provide the best extraction coverage.
    3. For JSON or JSON Lines, export event objects with an ID, timestamp, host, and available message or named EventData fields.
    4. For an existing EVTX file, download the local PowerShell converter, review it, and use its XML output. The original EVTX stays on your computer.

    See the README and input-format guide in the project source for examples. All sample identities, hosts, and network addresses are fictional.
