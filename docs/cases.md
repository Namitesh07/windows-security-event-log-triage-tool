# Save and reopen an investigation

## Save your work

After analysing a dataset, select **Save entire case** under Keep a report copy. This downloads a JSON file containing every accepted event, original source fields, source locations, case notes, finding annotations, analysis settings, and the selected rule profile.

Saving always includes the entire dataset, even when the table is filtered or the export-scope selector says Current evidence and filters. Annotations for findings removed by tuning are retained too. Check your browser's downloads before closing the tab.

There is no account, upload, browser storage, or automatic saving. A saved file can contain sensitive log content and notes; handle it like the source export.

## Continue later

1. Open the analyser and expand **Reopen a saved case** below the event chooser.
2. Choose your saved-case JSON file. An **Entire dataset** JSON report from v1.4.0 or later is also accepted.
3. The analyser validates the file, reconstructs event fields, and recalculates findings using the current engine.
4. Review the restored case title, notes, settings, profile, findings, and any version/timezone notice.

Reopening starts with all evidence visible. Finding review statuses are retained by stable rule/evidence identifiers. Notes for findings that no longer match remain in the case and in subsequent entire-dataset saves/exports.

Loading another dataset or case replaces the current case. Unsaved notes trigger the existing replacement confirmation. Invalid, cancelled, or unsupported files leave the current evidence and notes in place. Older pending operations cannot overwrite a newer selection.

## What is restored

| Item | Behaviour |
| --- | --- |
| Evidence | Original field/value pairs, accepted-record order, format, source record number, and source line |
| Source metadata | Original filename, byte size, available modification time, format, and collection diagnostics |
| Case context | Title, analyst, collection timezone, and case notes |
| Finding reviews | Status and note, including annotations outside current findings |
| Analysis | Effective threshold/window settings and validated rule profile |
| Findings | Recalculated from source fields; saved scores and normalized summaries are not trusted |
| Reopen provenance | Saved tool/rule versions, saved browser timezone, saved timestamp, reopened timestamp, and case filename in later reports |

A saved case preserves accepted event evidence, not a byte-for-byte copy of the original source file. For CSV rows rejected during the original import, diagnostics retain their locations/counts; rejected row contents were never part of the analysed dataset. XML retains each original Event substring; JSON retains the adapter's serialized original object.

## Compatibility and limits

- Saved-case envelope: kind **fieldnotes-case**, schemaVersion **1.1** (also accepts older 1.0 envelopes).
- Full JSON report compatibility: schemas **1.1 and 1.2**, generated by this tool from v1.4.0 onward.
- Filtered/scoped reports are refused because they cannot restore the whole investigation. Export Entire dataset instead.
- Hosted worker mode accepts case files up to **50 MB**; direct-file/no-worker mode remains limited to **2 MB**.
- Cases contain 1–100,000 accepted events, at most 2,048 fields per event, and field names up to 4,096 characters. Input-adapter limits still apply when initially opening event files.
- Existing note limits remain: title 200 characters, analyst/timezone 120 each, case notes 10,000, finding notes 4,000.
- Duplicate JSON keys, invalid or duplicated event identities, mismatched field layouts within one source/counts, invalid settings/profiles, and annotations pointing outside the dataset are rejected.
- Cases use the current known rule IDs/profile contribution layout. Unsupported future schemas or unknown profile rules require a compatible analyser version.

For a case larger than 50 MB, collect a narrower event range. JSON reports remain available separately, but a large report beyond the case limit cannot be reopened.

## Version and timezone context

Reopening is a fresh analysis of saved evidence, rather than replaying previously stored conclusions. A notice identifies differences between the saved and current tool/rule versions.

Explicit-offset timestamps keep their timezone meaning. Timezone-free timestamps are parsed in the browser's current timezone. If that differs from the saved browser timezone, the analyser displays a notice; compare timestamps and correlations before continuing. Collection timezone remains an analyst note and does not convert dates.

Saved cases and reports are user-provided JSON, not signed evidence or proof of authenticity. Re-analysis protects against trusting saved scores, but cannot establish that an input file has not been edited. See [report provenance](reports.md) and [rule profiles](rules.md).

## Multiple-file cases

Version 1.6.0 saves all original records, the source-file manifest, per-file diagnostics, and duplicate references in report schema 1.2 / envelope schema 1.1. Reopening validates each file and its field layout separately, reconstructs fields, and recalculates duplicate links, findings, and per-rule coverage. Saved duplicate flags, source display names, normalized summaries, and coverage states are not trusted. Older single-file v1.4/v1.5 reports and v1.5 envelope 1.0 cases remain readable. Source IDs and event UIDs are local references, not proof of authenticity. Older analyser versions cannot open the new schema.

See [collections](collections.md) and [coverage](coverage.md).

## Fingerprints and ATT&CK context in v1.7.0

Source SHA-256 values are optional, validated metadata with algorithm, hex digest, byte length, original-file-byte basis, and verification state. Reopening retains them as recorded-in-case, because cases contain accepted event evidence rather than complete original file bytes. Older cases remain readable without hashes. Current ATT&CK learning references are recalculated with findings from the bundled catalog; saved reference URLs/classifications are not trusted. Report schema 1.2 and envelope 1.1 remain unchanged, with additive metadata. Older analyser versions may drop newer metadata when resaving; use the current version to preserve it. See [fingerprints](fingerprints.md), [ATT&CK](attack.md), and [printing](printing.md).
